# Documentation

All project documentation is Docusaurus, in `documentation/`. There are no standalone
markdown files elsewhere in the repo.

| Directory            | Holds                                                           |
| -------------------- | --------------------------------------------------------------- |
| `docs/packages/`     | package API documentation                                       |
| `docs/architecture/` | how the project fits together                                   |
| `docs/guides/`       | how-to guides and tutorials                                     |
| `docs/journey/`      | the theory, research and non-obvious decisions behind a feature |

Run locally with `pnpm docs:dev` and build with `pnpm docs:build`. Both install with
`--ignore-workspace` first, because `documentation/` sits outside the pnpm workspace.
`sidebars.ts` is autogenerated, so a new page needs only `sidebar_position` frontmatter:

```markdown
---
sidebar_position: 1
---

# Your Title Here
```

## Style

Journey docs favour abstract prose, tables and Mermaid diagrams. They capture the _why_ —
what the problem was, what made it non-obvious, and the correct mental model — and include
at most the minimal formula needed to make the theory concrete. **No code snippets**: the
code is in the repo and will change; the reasoning is what has to survive.

Guides may carry code, but every snippet is a liability the moment the code moves.

## Keeping guides true

A guide that documents specific files declares them in a `Source files` note. When you
change a file a guide tracks, re-read the whole guide and fix every snippet, option name,
path and command the change affected — in the same change, not a follow-up. Find them with:

```sh
grep -rln "<path/you/changed>" documentation/docs/guides/
```

`pnpm docs:build` fails on broken internal links, so a clean build is real evidence that a
move did not leave dangling references.
